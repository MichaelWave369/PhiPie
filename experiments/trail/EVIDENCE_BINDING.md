# ΦTrail #17: private evidence binding and local consistency checks

**Experimental / offline / non-qualifying / no network or hardware commands**

PR #16 could validate a witness JSON containing arbitrary 64-character
checksums, but could not establish whether the referenced evidence files
actually existed. This rung is a local-only improvement: it **opens protected
files, recomputes checksums, and checks that host/radio/packet/receipt/path
contents agree with the operator's witness record**.

It does **NOT** authenticate HMAC signatures or verify key possession. It
does not prove hardware identity, board uniqueness, sensor truth, provenance
from another device, packet transport, routing, real Pi 5 boot, mesh coverage
or safety. Someone who fabricates mutually consistent local JSON can still
obtain `LOCAL_EVIDENCE_MATCH`. That means **file consistency**, not field
qualification.

## The seven evidence slots

| Manifest slot | Expected file / hash |
| --- | --- |
| `sender_host` | Local `field_cli host` JSON, verify self-checksum vs sender node's `host_snapshot_sha256`; platform/evidence origin agree |
| `sender_radio` | Standalone `radio_cli --interface` JSON or its `radio` wrapper, verify embedded `evidence_sha256` and radio authority flags |
| `receiver_host` | Same host check for receiver |
| `receiver_radio` | Same radio check for receiver |
| `handoff_packet` | Signed JSON generated by the two-node pilot, verify SHA-256 of **raw file bytes** equals witness `packet_sha256`, plus sender alias/organ |
| `handoff_receipt` | `two_node_cli receive --receipt-out` JSON, verify checksum of inner ObservationReceipt equals witness receipt digest, with matching evidence digest, packet identities and zero-authority flags |
| `path_test` | Operator-recorded JSON described below, SHA-256 of **raw file bytes**, cross-check path metrics to witness |

The file checksums use their **original producing formats**. The manifest
does not contain trusted cryptographic keys. Nothing is posted to GitHub.

## Private directory layout

Create the files yourself during an operator-supervised trial, with
`chmod 700` on the evidence directory and `chmod 600` on each file.
This code accepts *only* simple `.json` base filenames, refuses symbolic
links, directory escape, nonregular files, oversized records and duplicate
JSON keys. It opens the directory first and reads files relative to it.

Create a file manifest beside your witness file:

```bash
cd experiments/trail
python -m trailcore.evidence_cli manifest --output "$HOME/trail-field/manifest.json"
```

The manifest includes seven suggested names:
`sender-host.json`, `sender-radio.json`, `receiver-host.json`,
`receiver-radio.json`, `radio-packet.json`, `receive-receipt.json`,
and `path-observation.json`. Rename only the manifest's filename values
to point to the actual files already collected in your private directory.

**Path-test file example (operator-reported, not raw benchmark proof):**

```json
{
  "schema": "phipie-trail-path-evidence/v0.1",
  "kind": "ICMP",
  "packet_loss_pct": 0.0,
  "rtt_avg_ms": 12.3,
  "throughput_mbps": null,
  "independent_test_run": true,
  "evidence_origin": "OPERATOR_RECORDED_INDEPENDENT"
}
```

Store the *actual raw* ping or other testing evidence privately outside the
seven-file manifest. This normalized path record is an operator summary, not
a substitute for raw output review. For a `TCP_BENCHMARK` record, provide
a measured `throughput_mbps` value with its real supporting test output.
For `ICMP`, keep `throughput_mbps=null`; three pings cannot establish
end-to-end throughput.

Hashes entered into the witness must follow the rules in the table. The
inspector does **not** generate fake hashes to make the witness pass.

## Inspect privately

```bash
python -m trailcore.evidence_cli inspect \
  --witness "$HOME/trail-field/trial.json" \
  --manifest "$HOME/trail-field/manifest.json" \
  --evidence-dir "$HOME/trail-field/artifacts" \
  --output "$HOME/trail-field/binding-assessment.json"
```

Results are written with exclusive, owner-only file creation. Only per-slot
MATCH/HOLD, hash references, bounded reason codes and refusal authority
flags appear in stdout/assessment. No file paths, raw radio identifiers,
secrets or sensor data appear in results.

- `LOCAL_EVIDENCE_MATCH`: the completed witness and all seven file references
  are internally consistent. **Review candidate only.**
- `HOLD`: one or more records are unsafe, missing, inconsistent, malformed,
  or the underlying field witness was already incomplete.

The result **always** declares:

```text
filesystem_consistency_only = true
hmac_cryptographically_verified = false
field_identity_attested = false
sensor_measurement_attested = false
physical_hardware_qualified = false
mesh_transport_verified = false
action_authorized = false
network_change_authorized = false
rover_motion_authorized = false
```

## Acceptance and next steps

```bash
python -m unittest discover -s tests -v
python -m trailcore.evidence_cli --help
```

All GitHub CI fixtures are **synthetic local files**, not a physical two-Pi
qualification run. Subsequent stages require independent operator review of
**actual** raw Pi/driver, clock, network and replay tests, and stronger
device identity and secure transport. Keep source files and credentials
private; do not treat the operator's checkboxes as independent attestation.

**CAPABILITY != AUTHORITY. Local file integrity != radio truth.**
